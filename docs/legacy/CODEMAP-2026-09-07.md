## `.github/workflows/`

### `build-android.yml` · YAML (GitHub Actions)
- **What:** Reusable GitHub Actions workflow that builds and publishes the Android app (signed AAB to Google Play, universal APK to GitHub release).
- **Role:** One of three fan-out targets invoked by build.yml in the 12345APP CI repo. It checks out the private APP12345 app repo (which vendors the prebuilt librainbox.so ABIs), builds a release AAB + APK with Flutter, then ships them to Google Play and/or the GitHub release.
- **Key pieces:** jobs.build-android-app, workflow_call inputs {name,pkg,version}, step: Set build environment (versionCode), step: Setup Android signing, step: Build Android App Bundle and APK, step: Upload to Google Play Store, step: Upload APK/AAB to GitHub release
- **Talks to:** 12345APP/.github/workflows/build.yml (caller); private repo APP12345 (checked-out source; vendors librainbox.so); Google Play Console; GitHub Releases
- **Note:** Play upload is continue-on-error; the APK is always attached to the GitHub release, but the AAB is attached only when the Play upload fails. Android versionCode is derived from semver as a*100+b*10+c and sed-written into pubspec's version:X.Y.Z+BUILD. PKCS12 keystore (PKCS12_BASE64/NAME/PASSWORD) and Google service-account JSON are base64-decoded to disk on the runner — sensitive credentials.

### `build-apple.yml` · YAML (GitHub Actions)
- **What:** Reusable GitHub Actions workflow that builds and publishes iOS and macOS apps over a [ios, macos] matrix (IPA/PKG via xcrun altool).
- **Role:** One of three fan-out targets invoked by build.yml. Checks out the private APP12345 repo (which vendors librainbox.dylib inside each ServiceExtension), builds a signed IPA (iOS) or installer PKG (macOS), and uploads to App Store Connect with a GitHub-release fallback.
- **Key pieces:** jobs.build-apple-app, strategy.matrix.platform [ios, macos], workflow_call inputs {name,pkg,version}, step: Setup keychain and certificates, step: Install provisioning profiles, step: Build ${platform} app, step: Upload to App Store Connect, step: Clean up keychain / Clean up API key
- **Talks to:** 12345APP/.github/workflows/build.yml (caller); private repo APP12345 (checked-out source; vendors librainbox.dylib); Apple App Store Connect
- **Note:** Signing cert, provisioning profile, and App Store Connect API key (.p8) are decoded into a throwaway keychain / RUNNER_TEMP — sensitive; teardown steps are always()-guarded so they run even on build failure. macOS PKG requires the '3rd Party Mac Developer Installer' identity (distinct from app-signing cert). altool --type wants 'osx' for macOS, 'ios' for iOS. Upload step is continue-on-error with GitHub-release fallback.

### `build-windows.yml` · YAML (GitHub Actions)
- **What:** Reusable GitHub Actions workflow that builds and publishes the Windows app as an MSIX to the Microsoft Store.
- **Role:** One of three fan-out targets invoked by build.yml. Checks out the private APP12345 repo (which vendors windows/librainbox.{dll,lib,h}), enables Flutter native-assets so hook/build.dart stages librainbox.dll next to runner.exe, builds an unsigned Store MSIX, and publishes to the Microsoft Store with a GitHub-release fallback.
- **Key pieces:** jobs.build-windows-app, workflow_call inputs {name,pkg,version}, step: msstore reconfigure, step: Enable Windows desktop + native-assets, step: Build Windows app, step: Compose MSIX env (4-part version), step: Build MSIX package (Store) via dart run msix:create, step: Publish to Store
- **Talks to:** 12345APP/.github/workflows/build.yml (caller); private repo APP12345 (checked-out source; vendors librainbox.dll/.lib/.h + hook/build.dart); Microsoft Store / Partner Center
- **Note:** MSIX identity is passed entirely as CLI flags to msix:create (APP12345 has no msix_config block). --sign-msix false because the Store re-signs on ingestion. MSIX version is a 4-part X.Y.Z.0 (Store reserves revision 0). DISPLAY_NAME is derived by stripping PARTNER_APP's dotted namespace to its last segment. Partner Center creds (PARTNER_TENANT/SELLER/CLIENT/SECRET/CN/COMPANY/APP/STORE) are sensitive. Publish is continue-on-error -> release fallback.

### `build.yml` · YAML (GitHub Actions)
- **What:** Top-level orchestrator workflow that reads app identity from the private repo and fans out to the three platform build workflows.
- **Role:** Entry point of the store-release pipeline in the 12345APP CI repo. Triggered by the pubspec-updated repository_dispatch that APP12345's own ci.yml POSTs on a master version bump; resolves name/pkg/version and calls build-windows.yml, build-android.yml, and build-apple.yml.
- **Key pieces:** on.repository_dispatch types [pubspec-updated], on.workflow_dispatch, jobs.check-for-version (step get-info), jobs.build-windows / build-android / build-apple (uses: ./.github/workflows/build-*.yml)
- **Talks to:** APP12345/.github/workflows/ci.yml (dispatch source); private repo APP12345 pubspec.yaml + android/app/build.gradle.kts (identity source); 12345APP/.github/workflows/build-android.yml; 12345APP/.github/workflows/build-apple.yml; 12345APP/.github/workflows/build-windows.yml
- **Note:** name/version come from pubspec.yaml; pkg (bundle/application id) is grepped from android/app/build.gradle.kts applicationId. version output is prefixed with 'v' and consumed as the GitHub release tag by all three downstream workflows. Passes secrets: inherit so the reusable workflows see the signing/publishing secrets.

### `publish.yml` · YAML (GitHub Actions)
- **What:** Scheduled housekeeping workflow that mirrors the latest Store-published MSIX onto the private repo's GitHub release.
- **Role:** Independent of the build.yml fan-out. Runs daily (plus manual/self-edit triggers) to fetch the most recent Microsoft Store MSIX for the app and upload it to the GitHub release of the private APP12345 repo, backfilling the Windows artifact that build-windows.yml only attaches on a Store-publish failure.
- **Key pieces:** on.schedule cron '0 0 * * *', on.workflow_dispatch, on.push (self-edit of publish.yml), jobs.upload-to-release, action JasonWei512/Upload-Microsoft-Store-MSIX-Package-to-GitHub-Release
- **Talks to:** Microsoft Store (PARTNER_STORE store-id); private repo APP12345 GitHub Releases (target); 12345APP/.github/workflows/build-windows.yml (complements its fallback upload)
- **Note:** The MSIX upload step is continue-on-error so a day with no new Store package does not fail the scheduled run. Release asset name pattern is keyed on PKCS12_NAME (app name) with {version}/{arch} placeholders. Uses actions/checkout@v5 (older pin than the build workflows' v6).
